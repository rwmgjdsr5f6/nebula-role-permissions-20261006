3. 固定示例（alice / reader / documents:read）的可复现性核对
--------------------------------------------------------------------------------

用户期望的示例：合成成员 alice、角色 reader、权限 documents:read，围绕
同一份配置，演示查询已授予权限得到允许结果、查询未授予权限得到拒绝结
果。

核对结论：该示例在当前版本无法建立、无法执行、无法复现。缺失的步骤及
其影响如下：

  缺失步骤 1：初始化方式。
    README 与仓库中不存在任何初始化入口（无模块导入形式、无命令、无
    建库建表脚本）。影响：无法创建示例所需的"同一份配置"，示例没有
    前置状态的载体。

  缺失步骤 2：写入成员-角色关系的公开调用。
    没有任何公开入口可以把"alice 属于 reader"这一事实写入系统。
    影响：成员与角色的对应关系无法建立。

  缺失步骤 3：写入角色-权限规则的公开调用。
    没有任何公开入口可以授予"reader 拥有 documents:read"。
    影响：业务权限规则无法建立，"已授予"与"未授予"两种情形都无法构
    造。

  缺失步骤 4：执行判定的公开调用。
    没有任何公开入口接收（成员, 权限）输入并返回允许/拒绝。
    影响：允许结果与拒绝结果都无法产生，更谈不上与文档预期比对。

  缺失步骤 5：决定原因的输出。
    如第 2 节环节 E 所述，当前版本没有原因输出。影响：示例中"解释成
    员、角色、权限与决定原因之间的对应关系"无从谈起，这是当前版本
    的真实边界，不是示例写法问题。

由于上述每一步都缺失，本文档不提供"具体输入 -> 确定输出"的演示表格；
任何这样的表格都只能是虚构，违背本文档"只描述真实存在代码"的原则。
示例中涉及的权限名 documents:read 仅表示本地业务规则概念，与身份认证
或操作系统访问权限无关；当前版本连这一层业务规则也尚未实现。
